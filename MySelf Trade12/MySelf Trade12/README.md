# Myself Trade 12

Bybit와 Gemini API를 연동한 파이썬 자동 매매 프로그램입니다. 기본 대상 코인은 비트코인(BTC), 이더리움(ETH), 솔라나(SOL), 리플(XRP), 도지코인(DOGE) 다섯 가지이고, 설정에서 다른 코인을 직접 추가할 수 있습니다. 주문은 Bybit의 USDT 무기한 선물(Trade > Futures > Perpetual > USDT)로만 나갑니다.

두 가지 버전이 들어 있고, 같은 `.env` 파일을 함께 씁니다.

| 버전 | 실행 파일 | 어떤 것인가 |
|---|---|---|
| 간단 버전 | `autotrade.py` | 파일 하나. 1시간마다 Gemini에게 매수/매도/관망을 물어보고 주문. 맨 위 `TEST_MODE = True`로 가상 매매 |
| 전체 버전 | `main.py` | 대시보드 화면, 설정, 일일 손실 제한, 거래 기록과 엑셀, AI 회고와 학습까지 포함 |

처음에는 간단 버전을 `TEST_MODE = True`로 돌려 흐름을 익히고, 그다음 전체 버전의 모의 투자 모드로 넘어가는 순서를 권합니다.

## 버전 12에서 달라진 것

**버전 11에서 옮겨 올 때**: 새 폴더(MySelf Trade12)에 예전 폴더의 `.env` 파일과 `data` 폴더를 그대로 복사해 넣으면 API 키, 설정, 거래 기록, 학습 자료가 이어집니다. 새로 생긴 매도 방식은 기본값인 "AI 자동"으로 시작합니다. 예전처럼 익절가나 손절가에서 한 번에만 정리하고 싶으면 매매 설정에서 "일괄 매도"로 바꾸면 됩니다.

**1. 매도 방식: AI 자동 / 일괄 매도 / 분할 매도**

매수 방식과 같은 자리(매매 설정 > 거래 대상과 방향)에 "매도 방식"이 생겼습니다.

| 방식 | 어떻게 파는가 |
|---|---|
| AI 자동 (기본) | 살 때마다 AI(Gemini, 없으면 규칙 전략)가 그 포지션을 한 번에 팔지 나눠 팔지 정합니다. 보유 중에도 판단할 때마다 유지 / 일부 매도 / 전량 청산 중에서 고릅니다 |
| 일괄 매도 | 익절가나 손절가에서 전량을 한 번에 정리합니다 (버전 11까지의 방식) |
| 분할 매도 | 정한 횟수(2~5회)로 나눠 팝니다 |

- **분할 매도가 파는 자리**: 진입가에서 익절가까지 가는 길을 횟수만큼 구간으로 나눕니다. 3회면 1/3 지점에서 1회, 2/3 지점에서 1회를 팔고, 마지막 회차는 익절가(또는 손절가, 보유 시간 초과, AI 청산)에서 정리합니다. 한 회차에 파는 수량은 "남은 수량 / 남은 회차"입니다.
- **AI가 고르는 일부 매도**: 매도 방식이 AI 자동이나 분할 매도일 때, AI는 가격이 그 구간에 닿지 않았어도 "보유 방향의 힘이 약해졌다"고 보면 다음 회차를 먼저 팔 수 있습니다. 근거가 무너졌다고 보면 예전처럼 전량 청산을 고릅니다. 일괄 매도로 고정하면 일부 매도는 실행하지 않습니다.
- **손절가와 익절가는 그대로**: 일부를 판 뒤에도 남은 수량의 손절가와 익절가는 바뀌지 않습니다. 실제 계정에서는 팔 몫만 reduce-only 시장가로 내고, 거래소에 걸어 둔 손절/익절은 남은 수량에 그대로 적용됩니다.
- **팔지 않는 경우**: 구간에 닿았어도 가격 변동이 왕복 수수료의 1.5배보다 작으면(수수료를 빼면 남는 것이 거의 없는 자리) 팔지 않고 기다립니다. 수량이 거래소 최소 주문 단위에 가까워 나눌 수 없으면 한 번에 정리하기로 바꾸고 그 사실을 분석 화면에 남깁니다.
- **기록과 거래 횟수**: 나눠 판 몫은 기록에 한 줄씩 남고 사유에 "분할 매도 1/3 (익절가까지 40% 도달)"처럼 적힙니다. 그 몫의 손익은 판 순간에 확정됩니다. 하루 거래 횟수(최대 횟수 제한)는 포지션 하나를 전부 정리한 때 한 번으로 셉니다.
- **분할 매수와 함께 쓸 때**: 나눠 팔기 시작한 포지션에는 분할 매수의 남은 회차를 더 사지 않습니다.
- **화면**: 운용 상태 칸에 "매도 방식"이 나오고, 보유 포지션마다 "분할 매도 1/3"(또는 "일괄 매도") 표시와 다음 회차를 파는 가격이 나옵니다. 차트에도 다음 매도가가 점선으로 그려집니다.
- **알아 둘 점**: 분할 매도는 수익을 일찍 조금씩 확정하는 대신, 익절가까지 한 번에 간 거래에서는 일괄 매도보다 수익이 작습니다. 손절은 처음 구간에 닿기 전까지 전량에 그대로 적용됩니다. 추세가 길게 이어지는 가상 시세로 4일씩 돌려 본 점검에서는 일괄 매도 쪽 결과가 더 좋았습니다. 실제 시장은 다르게 움직이므로, 모의투자에서 두 방식을 며칠씩 비교해 본 뒤 정하는 것을 권합니다.

**2. 금융 사이트처럼 다듬은 화면**
- **시세 줄**: 대시보드 맨 위에 코인마다 지금 가격, 24시간 변동률(오르면 ▲ 빨강, 내리면 ▼ 파랑), 최근 24시간의 작은 그래프가 나옵니다. 누르면 아래 차트가 그 코인으로 바뀝니다(예전의 코인 탭을 대신합니다).
- **차트 머리말**: 고른 코인의 현재가와 24시간 변동률 옆에 24시간 고가, 저가, 거래 대금, 펀딩비, 화면 구간 변동률이 나옵니다.
- **차트**: 아래쪽에 거래량 막대가 생기고, 이동평균선 두 개(MA20 주황, MA60 보라)가 그려집니다. 차트 위 "이동평균선", "거래량" 버튼으로 각각 끄고 켤 수 있고, 고른 상태를 기억합니다.
- **어두운 화면**: 위쪽 상태 줄의 해 모양 버튼을 누르면 어두운 화면으로, 다시 누르면 밝은 화면으로 바뀝니다. 고른 화면은 다음에 열 때도 유지됩니다.
- **상태 줄**: 어느 화면에서든 총자산과 오늘 수익률이 보입니다. 누르면 수익률 화면으로 갑니다.
- 화면 아래에 버전과 위험 안내가 붙었습니다.
- 차트의 코인별 24시간 시세는 10초, 작은 그래프는 5분마다 새로 받습니다.

## 버전 11에서 달라진 것

**버전 10에서 옮겨 올 때**: 새 폴더(MySelf Trade11)에 예전 폴더의 `.env` 파일과 `data` 폴더를 그대로 복사해 넣으면 API 키, 설정, 거래 기록, 학습 자료가 이어집니다.

**1. 동시 보유 포지션 5개까지**
- 매매 설정 > 운영의 "동시 보유 포지션"에 1개부터 5개까지 넣을 수 있습니다(예전에는 4개까지). 기본 코인 다섯 가지를 한 번에 하나씩 모두 들 수 있습니다.
- 예전 최대값인 4개로 써 왔다면, 설정을 불러올 때 5개로 한 번 올려 줍니다. 4개나 그보다 적게 쓰고 싶으면 매매 설정에서 바꾸면 되고, 그 뒤에는 다시 바뀌지 않습니다.
- 포지션 하나의 투자금은 "오늘 원금 x 증거금 투자율 / 동시 보유 포지션 수"입니다. 5개로 늘리면 포지션 하나에 들어가는 금액은 그만큼 작아지고, 투자 한도 전체는 그대로입니다. 금액이 너무 작아 거래소 최소 주문 단위에 못 미치면 그 코인은 사지 않고 이유를 분석 화면에 남깁니다.
- 포지션이 늘면 같은 방향으로 한꺼번에 손실이 날 때의 폭도 커집니다. 레버리지를 높게 쓰는 경우에는 하루 청산 설정을 함께 확인하세요.

**2. 운용 상태에 다음 판단 시각**
- 대시보드의 운용 상태 칸 맨 위에 **다음 판단** 시각과 남은 시간(예: 17:02:00, 11분 32초 뒤)이 나옵니다. 남은 시간은 1초마다 줄어듭니다.
- 바로 아래 **판단 주기**에는 몇 분마다 판단하는지와 마지막으로 판단한 시각이 나옵니다.
- 자동 매매가 꺼져 있으면 "자동 매매가 꺼져 있음", 하루 청산 한도로 멈춘 날에는 "오늘은 매매 중지"로 표시됩니다.

## 버전 10에서 달라진 것

**버전 9에서 옮겨 올 때**: 새 폴더(MySelf Trade10)에 예전 폴더의 `.env` 파일과 `data` 폴더를 그대로 복사해 넣으면 API 키, 설정, 거래 기록, 학습 자료가 이어집니다.

**1. Gemini 서버가 혼잡할 때(HTTP 503)의 대응**
- 503은 Google 서버에 요청이 몰릴 때 나오는 일시적인 오류이고, API 키나 설정 문제가 아닙니다.
- 기본 모델이 응답하지 않으면 한 번 더 시도한 뒤 **예비 모델로 자동으로 넘어갑니다**. 예비 모델이 답하면 15분 동안은 그 모델을 먼저 부르고, 그 뒤 기본 모델을 다시 불러 응답하면 돌아옵니다.
- 예비 모델은 이 키로 쓸 수 있는 모델 목록에서 프로그램이 고릅니다(정식 Flash 모델 우선, 미리보기 모델은 뒤로). API 연결 화면에서 직접 정할 수도 있습니다.
- 모든 모델이 응답하지 않으면 오래 붙잡지 않고(기본 2번 + 예비 2개) 그 판단만 규칙 전략으로 대신합니다.
- **오늘의 계획 자동 전환**: 계획을 규칙 전략으로 세운 날(키가 없었거나 호출이 실패한 때), 이후 Gemini가 응답하면 계획을 AI 계획으로 자동으로 바꿉니다. 예전에는 "지금 다시 분석"을 눌러야 했습니다.
- 화면 문구를 실제 원인에 맞췄습니다. 키가 있는데도 "Gemini API 키가 없어"라고 나오던 문구를 고쳤고, 실패한 시각과 사유를 함께 보여 줍니다.
- **API 연결 화면에 Gemini 모델 선택**이 생겼습니다. 기본 모델과 예비 모델을 목록에서 고릅니다. 특정 모델이 자주 막히면 여기서 다른 모델로 바꾸면 됩니다.

**2. 보유 포지션의 익절/손절 직접 수정 (투자금 기준)**
- 익절과 손절은 지금처럼 기본은 자동으로 정해집니다.
- 대시보드의 보유 포지션마다 **"익절/손절 수정"** 버튼이 있습니다. 누르면 그 포지션의 투자금과 지금 걸려 있는 값(투자금 대비 %)이 채워진 창이 열리고, 비율(%)이나 금액(USDT)으로 고쳐 저장할 수 있습니다. 바꾸고 싶은 쪽만 고치면 다른 쪽은 그대로 둡니다.
- 예: 투자금 250 USDT, 익절 +10%로 걸린 포지션에서 익절을 20%로 바꾸면, 순수익이 50 USDT가 되는 가격을 계산해 그 가격으로 다시 겁니다. 실거래 모드에서는 Bybit에 걸린 익절/손절 주문도 함께 바뀝니다.
- 수수료를 모두 뺀 순손익 기준입니다. 손절은 투자금의 60%까지(강제 청산보다 먼저 나오도록), 익절은 가격이 진입가에서 50% 움직이는 지점까지 넣을 수 있습니다.
- 저장하면 바로 청산될 값(이미 지나친 익절이나 손절)은 받지 않고 이유를 알려 줍니다.
- 여기서 바꾼 값은 그 포지션에만 적용됩니다. 다음에 새로 사는 포지션은 다시 매매 설정의 방식을 따릅니다.

**3. 하루 목표와 하루 청산을 투자금 기준으로도 정하기 (매매 설정)**
- "하루 거래 수익 설정"과 "하루 청산 설정"에 **투자금 비율(%)** 방식이 생겼습니다. 이제 원금 비율, 투자금 비율, 금액 세 가지 중에서 고릅니다.
- 투자금은 "오늘 원금 x 증거금 투자율"입니다. 예: 원금 1,000 USDT, 투자율 10%면 투자금은 100 USDT이고, 투자금의 8%는 8 USDT(원금의 0.8%)입니다.
- 투자율이 낮을 때 투자금 기준 손실 한도를 작게 잡으면 원금 대비로는 아주 작은 값이 되어 그날 매매가 일찍 멈출 수 있습니다. 설정 칸 아래에 원금 대비 값과 금액이 함께 표시되니 확인하고 저장하세요.

**4. 차트 오른쪽 빈 공간**
- 차트를 왼쪽으로 끌면 최신 봉 오른쪽에 빈 공간이 생깁니다(화면의 80%까지). 현재가를 따라갈 때도 기본으로 12칸을 비워 둡니다.
- 비워 둔 폭은 기억해 두었다가 새 봉이 생겨도, 프로그램을 다시 열어도 유지합니다. 차트의 "현재 가격으로 돌아가기" 버튼을 누르면 기본 여백으로 돌아갑니다.

**5. 기본 코인에 솔라나(SOL) 추가**
- 기본 코인이 비트코인, 이더리움, 솔라나, 리플, 도지코인 다섯 가지가 되었습니다.
- 예전 설정을 불러올 때 거래할 코인에 솔라나를 한 번 넣어 줍니다. 원하지 않으면 매매 설정의 "거래할 코인"에서 끄면 되고, 그 뒤에는 다시 켜지지 않습니다. 예전에 직접 추가했던 솔라나는 기본 코인으로 합쳐집니다.
- 동시 보유 포지션 수(기본 2개)는 그대로입니다. 코인이 늘어도 한 번에 드는 포지션 수는 늘지 않습니다.

**6. 남은 금액과 직접 주문 (대시보드)**
- 대시보드 맨 위에 **남은 금액**이 표시됩니다. 총자산에서 지금 포지션에 들어가 있는 증거금을 뺀 값이고, 모의투자 모드에서는 가상 잔고 기준으로 같은 자리에 나옵니다. 모의투자 모드 화면에도 "투자 중"과 "남은 금액"이 있습니다.
- 보유 포지션 칸의 **"직접 주문"** 버튼을 누르면 주문 창이 열립니다. 코인, 방향(롱/숏), 투자금, 레버리지를 정하면 수량, 거래 금액, 수수료, 익절/손절 가격, 주문 뒤 남는 금액을 미리 보여 주고, 버튼을 누르면 시장가로 체결됩니다.
- 투자금은 남은 금액의 25%, 50%, 75%, 최대 버튼으로 고를 수 있습니다. 거래소 주문 단위(예: 비트코인 0.001개) 때문에 실제 투자금은 입력한 값보다 조금 작아질 수 있고, 그럴 때는 창에 표시됩니다.
- 익절/손절은 "자동"(그 코인의 변동성 기준)이 기본이고, "직접 입력"을 고르면 투자금 대비 %로 정할 수 있습니다.
- 직접 넣은 포지션은 자동 매매 포지션과 같은 규칙으로 관리됩니다: 익절/손절 가격에 닿으면 청산, 보유 시간 제한을 넘으면 시장가로 정리, 하루 청산 한도에 닿으면 전부 청산. 자동 매매가 켜져 있으면 AI 판단으로 청산될 수도 있습니다. 자동 매매가 꺼져 있어도 익절/손절과 보유 시간은 프로그램이 켜져 있는 동안 감시합니다.
- 한 코인에는 포지션을 하나만 둡니다. 직접 넣은 포지션도 동시 보유 포지션 수에 들어가서, 한도가 차 있으면 자동 매매는 새로 사지 않습니다.
- 지정가 주문은 없고 시장가 주문만 됩니다. 실전 거래 모드에서는 주문 전에 한 번 더 확인을 받습니다. 하루 청산 한도로 잠긴 날에는 직접 주문도 받지 않습니다.

**7. 기록의 달력**
- 기록 화면 오른쪽 위의 달력 버튼("날짜로 보기")을 누르면 달력이 열립니다. 수익이 난 날은 빨간색, 손실이 난 날은 파란색으로 표시되고 그날의 순손익이 함께 나옵니다.
- 날짜를 고르면 그날의 수익 합계, 손실 합계, 순손익, 하루 수익률, 거래 횟수, 승률과 그날 청산한 거래, 그날의 계획과 회고, **그날 한 분석 전부**를 볼 수 있습니다.
- 분석은 처음에 15개가 나오고, "더 보기"를 누를 때마다 20개씩 이어서 나옵니다. 그날의 마지막 분석까지 계속 볼 수 있습니다.
- 지난 날짜의 분석을 볼 수 있도록 판단 기록 보관량을 늘렸습니다(약 3,000건에서 100,000건으로). 버전 9까지 쓰면서 이미 지워진 오래된 분석은 되살릴 수 없고, 이제부터 쌓이는 기록이 보관됩니다.

**8. 화면 디자인**
- 화면 위에 **상태 줄**을 두었습니다. 어느 화면에서든 거래 모드, 자동 매매 스위치, AI 연결 상태, 다음 판단 시각을 보고 자동 매매를 켜고 끌 수 있습니다.
- 대시보드 맨 위에 총자산, 오늘 수익률(청산 한도와 목표 사이의 위치), 오늘 거래, 보유 포지션을 한 줄로 모았습니다. 코인 탭은 차트 위로 옮겼습니다.
- 왼쪽 메뉴를 "거래"와 "설정"으로 나누고 대시보드 항목을 추가했습니다. 이름도 하는 일에 맞게 바꿨습니다(설정 -> 매매 설정, API -> API 연결, MAIL -> 메일 보고서).
- 매매 설정을 다섯 묶음(거래 대상과 방향, 투자금과 레버리지, 수익과 손실 기준, 거래 횟수와 보유 시간, 운영)으로 나누고, 위쪽 버튼으로 바로 이동할 수 있게 했습니다. 값을 바꾸면 "저장하지 않은 변경이 있습니다"라고 알려 주고, 저장하지 않고 다른 화면으로 가려 하면 한 번 물어봅니다.
- 글꼴을 Pretendard로 바꿨습니다(인터넷이 안 되면 맑은 고딕으로 표시됩니다).

## 버전 9에서 달라진 것

요구사항 문서(v2)의 8가지와, 원하는 코인만 매수하는 기능을 넣었습니다.

**1. 익절/손절을 두 가지 기준으로 분리 (설정)**
- **전체 원금 기준** (하루 단위): "하루 거래 수익 설정"과 "하루 청산 설정"을 비율(%) 또는 금액(USDT) 중에서 골라 정합니다. 금액으로 정하면 오늘 원금으로 나눠 %로 바꿔 적용합니다. 예: 원금 1,000 USDT에서 -250 USDT는 -25%.
- **해당 회차 진입 투자금 기준** (포지션 단위): "포지션 익절 / 손절" 칸에서 AI 자동과 수동 설정을 고릅니다.
  - 수동 설정: 익절과 손절을 각각 비율(슬라이더 또는 숫자 입력)이나 금액으로 정합니다. 예: 투자금의 50% 익절, 20% 손절. 수수료를 모두 뺀 순손익 기준이라, 투자금 100 USDT에 50%면 순수익이 50 USDT일 때 익절됩니다. 프로그램이 이 값을 레버리지에 맞는 가격으로 바꿔 주문에 겁니다.
  - AI 자동: Gemini가 그 코인의 변동성(ATR)과 최근 고점/저점, 캔들 구조를 보고 거래마다 폭을 따로 정합니다. Gemini 키가 없으면 변동성(ATR) 기준으로 계산합니다.
  - 손절은 투자금의 60%까지만 넣을 수 있습니다. 강제 청산보다 먼저 손절이 나오게 하기 위한 제한입니다. 그 코인의 최대 레버리지에 가까운 배율에서는 강제 청산이 더 가까워서, 프로그램이 손절을 조금 더 좁게(투자금의 40%대까지) 겁니다.
  - 손절 비율이 작은데 레버리지가 높으면 수수료만으로 그 손실을 넘게 됩니다(50배에서 왕복 수수료는 투자금의 약 5.5%). 이럴 때는 정해 둔 손실을 지키는 쪽을 택해 그 거래의 레버리지를 낮추고, 이유를 분석 화면에 남깁니다. 예: 손절 3%는 14배 이하에서만 지킬 수 있습니다. 설정 화면의 예시 문구에도 그대로 나옵니다.
  - 익절은 가격이 50% 움직이는 지점까지만 겁니다. 낮은 레버리지에 큰 익절 비율(예: 3배에 300%)을 넣으면 가격이 100% 넘게 움직여야 해서, 숏의 익절 가격이 0 아래로 내려가기 때문입니다.
  - 금액으로 정했을 때 분할 매수는 "다 샀을 때의 투자금" 기준입니다. 바꾼 값은 다음에 새로 사는 포지션부터 적용됩니다.
  - 하루 청산 설정(원금 기준 손실 한도)은 익절/손절을 AI 자동으로 두어도 항상 적용됩니다.
- 대시보드의 보유 포지션마다 "익절 시 +X USDT (+N%), 손절 시 -Y USDT (-M%)"가 표시됩니다.

**2. 포지션 보유 시간 제한 (설정)**
- 5분에서 1440분(24시간)까지 넣을 수 있습니다. 1440을 넘는 값은 입력하는 즉시 1440으로 막히고, 5 미만이나 빈 칸은 빨간 안내 문구가 나오며 저장되지 않습니다. 화면을 거치지 않고 들어온 값도 서버가 같은 범위로 거부합니다.

**3. 롱/숏 균형**
- 규칙 전략을 다시 짰습니다. 롱과 숏을 완전히 같은 기준(거울상)으로 채점하고, 두 점수의 차이가 작으면 관망합니다. 예전처럼 동점일 때 롱을 고르지 않습니다.
- 장세를 상승 추세 / 하락 추세 / 박스권으로 나눕니다(1시간봉의 추세 효율, 추세선 기울기, 고점과 저점의 구조).
  - 하락 추세: 숏으로 진입합니다. 이동평균이 아직 완전히 돌아서지 않은 하락 전환 초기도 인식합니다.
  - 박스권: 박스 상단(볼린저 상단, RSI 60 이상)에서 숏, 하단에서 롱만 짧게 잡습니다. 박스 중간에서 추세를 따라가는 진입은 하지 않습니다.
- Gemini에게는 롱 확률과 숏 확률을 따로 평가하게 하고, 둘의 차이가 0.15보다 작으면 진입하지 않습니다. 하락장과 박스권에서 숏을 예외로 취급하지 않도록 지시문을 고쳤습니다.
- 최근 24시간 진입이 한 방향으로 80% 이상 쏠려 있는데 지금 장세가 그 방향이 아니면, 그 방향의 진입 기준을 조금 올립니다.
- 참고: 가상 시세로 예전 규칙 전략을 돌려 보면 롱 쏠림은 나타나지 않았습니다(오히려 숏이 더 많았습니다). 보신 24시간의 롱 쏠림은 그 기간의 시장 방향이나 Gemini의 판단 성향 때문일 가능성이 있습니다. 그래서 규칙 쪽 보완과 함께 Gemini 지시문, 상호 검증을 같이 손봤습니다. 실제 시장에서 균형이 어떻게 나오는지는 모의투자로 다시 확인해 주세요.

**4. 손익 현황과 거래 기록**
- 수익률 화면 맨 위에 "오늘 손익 현황": 오늘 수익, 오늘 손실, 순손익을 달러와 원화, 원금 대비 %로 크게 보여 주고, 코인별 막대 그래프와 비중 원 그래프를 그립니다.
- 그 아래 수익 표(빨강)와 손실 표(파랑): 코인명, 거래 금액, 수익률, 수익금.
- 합계는 대시보드의 오늘 수익과 같습니다. 오늘 청산한 거래와 보유 중인 포지션(지금 청산한다고 봤을 때)을 더한 값이고, 어제부터 들고 온 포지션은 오늘 0시 이후의 손익만 셉니다.
- 원화는 1 USDT의 원화 가격(업비트 USDT/KRW, 안 되면 공개 환율)으로 환산합니다. 환율을 못 받으면 달러만 표시합니다. 달러 표시는 1 USDT를 1달러로 본 값입니다.
- 대시보드 거래 기록 아래에 "더보기 (Load More)" 버튼: 누를 때마다 10건씩, 지난 날의 거래까지 이어서 보여 줍니다.

**5. 글로벌 지수와 금 시세 (분석 화면)**
- 분석 화면 맨 위에 나스닥, 다우존스, S&P 500, 국제 금 시세가 카드로 나옵니다(현재 값, 전일 대비, 5일, 1개월, 한 달 흐름 선).
- 예전에는 이 값들을 받아 오기만 하고 화면에는 그리지 않았고, 자동 매매를 켜기 전에는 받아 오지도 않았습니다. 이제 프로그램을 켜면 바로 받아 옵니다.
- 받아 오는 곳도 늘렸습니다. Yahoo Finance가 막히면 지수는 FRED(미국 연준 공개 자료, 전일 종가), 금은 gold-api.com(현물)에서 대신 받고, 실패하면 이유를 화면에 적습니다.
- 이 시세는 Gemini 키가 없어도 표시됩니다. Gemini 키를 저장하면 바로 연결을 확인하고 AI 분석을 다시 돌려서, 지수를 해석한 내용이 "오늘의 계획"에 나옵니다.

**6. 투자금 기준 익절/손절 조절**: 1번의 "포지션 익절 / 손절" 칸입니다. 슬라이더와 숫자 입력 칸이 서로 맞춰 움직입니다.

**7. 진입 시각과 청산 시각 분리**: 대시보드, 기록 화면의 표, 엑셀 모두 "진입 시각"과 "청산 시각"을 따로, 초 단위까지 표시합니다.

**8. Gemini 연결 상태와 학습 자료**
- Gemini 키를 저장하면 바로 연결을 확인합니다. 성공하면 "Gemini API가 성공적으로 연결되었습니다" 알림이 뜨고, 왼쪽 아래와 API, 분석 화면에 초록색 "연결됨 (Connected)" 표시가 켜집니다.
- 새 메뉴 **학습 자료**: 전략 글, 유튜브 영상 링크, 차트 이미지를 올리면 Gemini가 규칙으로 정리해 지식 베이스에 넣고, 이후 모든 계획과 매매 판단에 함께 참고합니다. 자료마다 켜고 끄기, 다시 분석, 삭제를 할 수 있습니다.
  - Gemini 앱(gemini.google.com)의 대화나 그곳에 올린 파일은 프로그램이 읽을 수 없습니다. 구글이 그 내용을 API로 내주지 않기 때문입니다. 자료는 이 화면에 올려 주세요.
  - 자료는 Gemini 키가 없어도 저장해 둘 수 있고, 키가 연결되면 그때 분석합니다. 자료를 읽고 정리하는 것도, 정리한 규칙을 쓰는 것도 Gemini라서 키가 없는 동안에는 판단에 반영되지 않습니다.
  - 자료가 많으면 최신 자료부터 정해진 분량(약 7,000자)까지만 AI에 전달합니다. 화면의 "AI 판단에 쓰는 자료" 수가 실제로 전달되는 자료 수입니다.
  - 유튜브는 공개 영상만 읽을 수 있고, 긴 영상은 무료 사용량을 많이 씁니다. 실패하면 영상의 핵심을 글로 적어 올리는 방법이 확실합니다.
- **AI 상호 검증** (설정, 기본 켜짐): Gemini의 진입 판단을 프로그램의 규칙 점수와 맞춰 봅니다. 규칙 점수가 같은 방향을 가리킬 때만 진입하고, 두 값을 합친 종합 확신도가 기준을 넘어야 주문합니다. 분할 매수의 추가 회차도 같은 확인을 거칩니다. 어긋나서 막힌 판단은 이유와 함께 분석 화면의 "모든 판단"에 남습니다.
- Gemini 호출이 실패하면(사용량 제한, 응답 지연 등) 그 판단은 규칙 전략으로 대신하고, 연결 표시가 "연결됨, 최근 호출 실패"(노란 점)로 바뀌며 분석 화면에 이유가 나옵니다. 이때는 맞춰 볼 AI 판단이 없으므로 상호 검증도 적용되지 않습니다.
- Gemini의 답을 기다리는 동안(한 번에 최대 45초쯤)에는 모의투자의 손절/익절 확인이 그만큼 늦어질 수 있습니다. 실제 계정의 손절/익절은 거래소에 걸려 있어 영향이 없습니다.

**추가. 원하는 코인만 매수 (설정 > 거래할 코인)**
- 눌러서 켠 코인만 새로 삽니다. 한 개만 켜면 그 코인에 집중합니다.
- "다른 코인 추가": 기본 코인 말고도 Bybit USDT 무기한 선물에 있는 코인을 영문 약자(예: SOL)로 추가할 수 있습니다. Bybit에 실제로 있는 코인인지 확인한 뒤 목록에 넣고, 대시보드의 코인 탭과 차트에도 나옵니다. 최대 8개.
- 직접 추가한 코인은 "목록에서 지우기"로 뺄 수 있습니다. 보유 중인 코인은 청산한 뒤에 지울 수 있고, 지난 거래 기록은 남습니다. 그 코인 하나만 거래하도록 골라 둔 상태에서는 지울 수 없습니다(다른 코인이 대신 켜져 거래되는 일을 막기 위해서입니다). 다른 코인을 먼저 켜고 저장한 뒤 지우세요.
- 추가한 코인은 기본 코인보다 거래량이 적고 변동이 큰 경우가 많습니다. 최대 레버리지와 최소 주문 단위도 코인마다 달라서, 프로그램이 Bybit에서 받아 온 값에 맞춰 주문합니다.

## 버전 8에서 달라진 것

- **투자금 합계가 원금을 넘던 오류 수정**: 새 포지션을 살 때 "이번 포지션 하나에 얼마"만 계산하고, 이미 들어가 있는 투자금과의 합계는 확인하지 않던 문제를 고쳤습니다. 동시 보유 포지션 수를 포지션을 들고 있는 중간에 바꾸면(예: 2개에서 4개), 먼저 산 포지션(원금의 절반)과 나중에 산 포지션(원금의 4분의 1)이 섞여 합계가 원금을 넘을 수 있었습니다.
  - 이제 모든 포지션의 투자금(증거금) 합계는 **투자 한도 = 오늘 원금 x 증거금 투자율**을 넘지 않습니다. 설정을 중간에 바꿔도 마찬가지입니다.
  - 남은 한도가 포지션 하나 몫보다 작으면 남은 만큼만 사고, 한도를 다 썼으면 새로 사지 않습니다. 이유는 분석 화면의 "모든 판단"에 남습니다.
  - 대시보드 원금 칸에 "투자 중 X USDT (한도의 N%)"로 표시됩니다.
  - 예전 버전에서 이미 한도를 넘겨 산 포지션은 그대로 두고, 합계가 한도 아래로 내려올 때까지 새로 사지 않습니다.

## 버전 7에서 달라진 것

- **투자 금액도 오늘 원금 기준**: 포지션에 넣는 증거금을 "오늘 원금 x 증거금 투자율 / 동시 보유 포지션 수"로 계산합니다. 이전에는 진입하는 순간의 총자산을 기준으로 해서, 하루 중에 수익이나 손실이 날 때마다 투자 금액이 조금씩 달라졌습니다.
  - 오늘 원금은 그날 0시(선택한 시간대)의 총자산입니다. 하루 중에는 바뀌지 않습니다.
  - 수익이나 손실이 난 뒤에는 그 결과 금액이 다음 날의 원금이 됩니다.
  - 하루 목표 수익, 하루 청산 퍼센트, 투자 금액 세 가지가 모두 같은 원금을 기준으로 합니다.
  - 예: 오늘 원금 1,000 USDT, 투자율 100%, 포지션 2개면 포지션 하나에 500 USDT. 오전에 손실이 나서 총자산이 950이 되어도 다음 포지션은 500 USDT 기준으로 삽니다. 다음 날에는 그날 0시의 총자산이 새 원금이 됩니다.
  - 다만 실제로 남아 있는 자산보다 많이 쓸 수는 없어서, 손실로 자산이 부족하면 남은 만큼만 삽니다. 진입 수수료 몫도 남겨 두기 때문에 투자율 100%에서는 포지션 금액이 500보다 조금 작을 수 있습니다.
  - 분할 매수로 나눠 살 때도 한 포지션의 투자 금액이 이 한도를 넘지 않습니다.
- 설정 화면의 증거금 투자율 칸과 대시보드의 원금 칸에 "오늘 원금 x 투자율 = 투자 한도"가 금액으로 표시됩니다.
- 엑셀의 "사용 원금 비율"도 오늘 원금 대비로 기록합니다.

## 버전 6에서 달라진 것

- **거래할 코인 선택** (설정): 비트코인, 이더리움, 리플, 도지코인 중에서 거래할 코인을 고릅니다. 고른 코인만 새로 삽니다. 한 개만 고르면 증거금 투자율 전체를 그 코인에 씁니다. 고르지 않은 코인에 이미 보유 중인 포지션은 정리될 때까지 계속 관리합니다.
- **매수 방식 선택** (설정): AI 자동 / 일괄 매수 / 분할 매수.
  - AI 자동: 살 때마다 Gemini가 한 번에 살지 나눠 살지 정합니다. Gemini 키가 없으면 규칙 전략이 정합니다(확신도가 0.7 미만이거나 변동성이 크면 분할).
  - 일괄 매수: 항상 한 번에 전량을 삽니다.
  - 분할 매수: 정한 횟수(2~5회, 기본 3회)로 나눠 삽니다. 첫 회차를 산 뒤, 판단 주기마다 보유 방향의 근거가 유지된다고 판단되면 다음 회차를 삽니다. 근거가 약해지면 남은 회차는 사지 않습니다.
  - 추가로 살 때마다 평균 단가가 바뀌므로 손절가와 익절가도 새 평균 단가 기준으로 다시 잡습니다. 실제 계정에서는 Bybit 포지션의 손절/익절도 함께 바꿉니다.
  - 분할 매수 중인 포지션은 원금 칸에 "분할 2/3"처럼 표시되고, 추가로 산 이유는 분석 화면에 "추가 매수"로 남습니다.
  - 분할 매수의 추가 회차는 거래 횟수에 따로 세지 않습니다. 진입부터 청산까지가 1회입니다.
- **하루 목표와 하루 청산은 오늘 원금 기준**: 원금은 그날 0시(선택한 시간대)의 총자산입니다. 수익이나 손실이 난 뒤에는 그 결과 금액이 다음 날의 원금이 되고, 하루 중에는 바뀌지 않습니다. 설정 화면과 대시보드에 "원금 1,000 USDT 기준 목표 1,500 / 청산 750"처럼 금액으로 함께 표시합니다.

분할 매수는 진입 시점을 나누는 방법일 뿐 손실을 막아 주지는 않습니다. 가격이 불리하게 움직이는 동안 계속 사면 손실이 커질 수 있어서, 프로그램은 방향 근거가 유지될 때만 추가로 사고 남은 일일 손실 한도를 넘는 수량은 사지 않습니다.

- 원금 칸의 보유 포지션마다 "청산" 버튼 옆에 구매 시각(진입한 시각, 선택한 시간대 기준)을 표시합니다. 마우스를 올리면 보유한 시간이 나옵니다.

## 버전 4에서 달라진 것

- 차트를 상장 시점까지 거슬러 볼 수 있습니다. 화면을 과거로 옮기면 그 이전 시세를 자동으로 이어서 불러옵니다.
- 마우스 휠: 내리면 축소(봉이 작아지고 더 긴 기간이 보임), 올리면 확대. 마우스가 있는 위치를 기준으로 확대/축소됩니다.
- 마우스로 누른 채 좌우로 끌기: 시간대를 옮겨 그 당시의 차트를 봅니다.
- 차트 오른쪽 아래 버튼
  - 화살표: 현재 시간으로 이동합니다. 과거를 보고 있을 때 진하게 표시됩니다.
  - 전체: 불러올 수 있는 전체 기간을 한 화면에 보여 줍니다.
  - `-`, `+`: 축소와 확대 (휠이 없는 기기용).
- 한 번에 화면에 담는 봉은 최대 6,000개입니다. 1분봉이나 15분봉으로는 상장 시점까지 한 화면에 담을 수 없으니, 상장부터 지금까지를 한눈에 보려면 일봉, 주봉, 월봉에서 "전체"를 누르세요.
- 과거 구간을 보는 중에도 현재가는 계속 갱신되고, 십자선의 "현재가 대비 %"는 지금 가격을 기준으로 계산됩니다.

## 버전 3에서 달라진 것

- 수익 표시를 모두 "수수료를 뺀 순수 금액"으로 통일했습니다. 보유 포지션의 손익 합계와 오늘 수익이 맞아떨어집니다.
  - 포지션별 손익 = 가격 손익 - 진입 수수료(이미 낸 것) - 청산 수수료(지금 청산하면 낼 예상액). 그 아래 줄에 내역이 그대로 표시됩니다.
  - 원금(총자산)과 오늘 수익률도 같은 기준입니다. "지금 전부 청산하면 손에 남는 금액"이라서, 청산해도 숫자가 갑자기 줄지 않습니다.
  - 수익률 칸에 "청산 완료 + 보유 중 = 오늘 수익"과 오늘 낸 수수료 합계가 표시됩니다.
  - 일일 손실 제한과 목표 달성도 이 순수 금액으로 판단합니다.
  - 실제 Bybit 계정에서는 Bybit 화면의 자산이 이 프로그램의 원금보다 청산 수수료 예상분만큼 크게 보입니다. Bybit는 아직 내지 않은 청산 수수료를 빼지 않기 때문입니다. 펀딩비(8시간마다 오가는 비용)는 자산에는 반영되지만 포지션별 숫자에는 따로 나오지 않습니다.
- 코인 순서를 비트코인, 이더리움, 리플, 도지코인으로 바꿨습니다.
- MAIL: 받는 주소만으로 보내는 간편 발송, 받는 주소 추가와 삭제.

레버리지가 높을수록 수수료가 커진다는 점이 숫자로 보입니다. 왕복 수수료는 거래 금액의 약 0.11%인데, 26배면 증거금의 약 2.9%입니다. 즉 26배 포지션은 가격이 유리하게 0.11% 넘게 움직여야 본전입니다.

- 메인 차트: 크기 확대, 봉차트/선차트 전환, 타임프레임 13종, 십자선, 익절/손절선의 진입가 대비 %

- MAIL 메뉴: 매일 21시 일일 보고서 메일. 받는 주소만 넣으면 되고(비밀번호, 2단계 인증 불필요), 주소를 여러 개 추가하고 삭제할 수 있음

- 참고 채널 4곳과 ICT/SMC, 프라이스 액션, 스캘핑, 금 흐름 방법론을 `methodologies.json`에 반영
- 왼쪽 아래 고정 시계

## 먼저 알아 둘 점

- **수익은 보장되지 않습니다.** 설정의 "하루 목표 수익률 30%"는 프로그램이 달성해 주는 값이 아니라 기준선입니다. 하루 30%는 어떤 전략으로도 꾸준히 낼 수 없는 수준이고, 그만큼을 노리면 손실 한도(-25%)에 닿는 날이 훨씬 많아질 수 있습니다.
- **레버리지는 손실도 같은 배수로 키웁니다.** 50배에서는 가격이 2%만 반대로 움직여도 증거금이 전부 사라집니다. 수수료 부담도 배수로 커집니다(왕복 약 0.11% x 레버리지 = 증거금 대비 비용).
- **Bybit는 거주 국가에 따라 이용이 제한됩니다.** Bybit 고객센터의 서비스 제한 국가 목록에는 미국, 캐나다, 중국 본토, 홍콩, 싱가포르 등이 올라 있습니다. 본인 거주지에서 이용할 수 있는지 먼저 확인하세요.
- **실제 거래소 연결은 본인 컴퓨터에서 처음 검증됩니다.** 이 프로그램은 가상 시세와 가짜 응답으로 계산과 주문 흐름을 점검했지만, 만든 환경에서는 Bybit, Gemini, Yahoo, FRED, 업비트 서버에 접속할 수 없어 실제 통신은 확인하지 못했습니다. 글로벌 지수 수신, 유튜브 링크와 차트 이미지 분석, 코인 추가 때의 Bybit 확인도 마찬가지입니다. 그래서 아래 순서(테스트 모드 -> 모의 투자 -> 데모 트레이딩 -> 소액 실전)를 꼭 지켜 주세요.

## 1단계. 설치

1. VS Code에서 `파일 > 폴더 열기`로 `myself_trade` 폴더를 엽니다.
2. `터미널 > 새 터미널`을 엽니다.
3. 가상 환경을 만들고 켭니다.

   Windows:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   ```

   macOS:
   ```
   python3 -m venv .venv
   source .venv/bin/activate
   ```
   터미널 줄 앞에 `(.venv)`가 보이면 된 것입니다.

4. 패키지를 설치합니다.
   ```
   pip install -r requirements.txt
   ```
   간단 버전만 쓸 거라면 이것만 설치해도 됩니다.
   ```
   pip install pybit python-dotenv google-genai schedule
   ```

5. 설치가 잘 됐는지 확인합니다. 인터넷이나 API 키 없이 돌아갑니다.
   ```
   python selftest.py
   ```
   마지막 줄에 "모두 정상입니다"가 나오면 됩니다.

## 2단계. API 키 준비 (.env)

전체 버전(`main.py`)을 쓴다면 파일을 직접 만들 필요 없이, 대시보드 왼쪽 메뉴의 **API** 화면에 키를 붙여 넣고 저장하면 됩니다. 그 화면이 아래 `.env` 파일을 대신 만들어 줍니다. 간단 버전(`autotrade.py`)만 쓸 때는 아래처럼 직접 만듭니다.

1. `.env.example` 파일을 복사해서 이름을 `.env`로 바꿉니다.
2. 등호 오른쪽에 키를 붙여 넣습니다. 따옴표와 띄어쓰기는 넣지 않습니다.

   ```
   BYBIT_API_KEY=여기에_바이비트_API_키
   BYBIT_SECRET_KEY=여기에_바이비트_시크릿
   GEMINI_API_KEY=여기에_제미나이_키
   ```

키를 받는 곳:

- **Gemini**: Google AI Studio(aistudio.google.com)에서 `Get API key`.
- **Bybit**: 로그인 후 `API 관리 > 새 키 생성 > 시스템 생성 API 키`.
  - 권한은 `읽기-쓰기`, `통합 거래(계약: 주문, 포지션)`만 켭니다.
  - **출금 권한은 절대 켜지 마세요.**
  - 가능하면 본인 IP만 허용하도록 제한을 겁니다.
- **Bybit 데모 트레이딩**: Bybit 화면에서 `데모 트레이딩`으로 전환한 뒤, 그 안에서 API 키를 따로 만듭니다. 가상 자금으로 실제 주문 흐름을 시험할 수 있습니다.

`.env` 파일은 비밀번호와 같습니다. 다른 사람에게 보내거나 인터넷에 올리지 마세요.

## 3단계. 간단 버전 실행 (autotrade.py)

1. `autotrade.py` 맨 위 설정을 확인합니다.

   ```python
   TEST_MODE = True        # True면 실제 주문 없이 화면 출력만
   MARKET_TYPE = "linear"  # "linear" 선물 / "spot" 현물
   ORDER_USDT = 30         # 한 번 주문 금액
   LEVERAGE = 5
   INTERVAL_MINUTES = 60   # 60 = 1시간마다
   ```

2. 한 번만 실행해 봅니다.
   ```
   python autotrade.py --once
   ```
   코인별 가격, Gemini의 판단(매수/매도/관망)과 이유, 그리고 `[테스트] 주문하지 않음`이 출력됩니다. `TEST_MODE = True`에서는 Bybit 키 없이도 돌아갑니다(Gemini 키는 필요).

3. 주기적으로 돌립니다.
   ```
   python autotrade.py
   ```
   시작하자마자 한 번 실행하고, 이후 `INTERVAL_MINUTES` 분마다 반복합니다. 끝낼 때는 `Ctrl + C`.

   주기를 바꾸는 방법은 `main()` 함수 안에 있습니다.
   ```python
   schedule.every(INTERVAL_MINUTES).minutes.do(job)   # N분마다
   schedule.every().hour.at(":01").do(job)            # 매시 1분에
   schedule.every().day.at("09:00").do(job)           # 매일 오전 9시에
   ```
   터미널 창을 닫거나 컴퓨터가 절전에 들어가면 멈춥니다.

4. 판단 기록은 `autotrade_log.csv`에 쌓입니다(엑셀로 열림). 며칠 지켜본 뒤 실제 주문을 내려면 `TEST_MODE = False`로 바꿉니다.

선물에서 판단의 의미: 매수 = 롱 진입(숏을 들고 있으면 청산), 매도 = 숏 진입(롱을 들고 있으면 청산). 반대 포지션이 있으면 그 주기에는 청산만 하고, 새 진입은 다음 주기에 다시 판단합니다.

## 4단계. 전체 버전 실행 (main.py)

```
python main.py
```

브라우저에서 `http://127.0.0.1:8000`이 열립니다. 이 주소는 본인 컴퓨터에서만 접속됩니다. 끝낼 때는 터미널에서 `Ctrl + C`.

### 화면

- **대시보드**: 맨 위에 코인 시세 줄(누르면 차트의 코인이 바뀜), 그 아래 총자산과 오늘 수익률, 코인 차트, 거래 기록, 오른쪽에 운용 상태(다음 판단, 레버리지, 매수 방식, 매도 방식 등)와 보유 포지션, 오늘 수익률 흐름. 자동 매매 On/Off 스위치는 화면 위 상태 줄에 있습니다.
  - 차트: 봉차트(양봉 빨강, 음봉 파랑)와 선차트 전환, 타임프레임 13종(1/3/5/15/30분, 1/3/6/12시간, 일/주/월/년봉). 3시간봉과 년봉은 Bybit에 없어서 1시간봉과 월봉을 묶어 만듭니다.
  - 이동과 확대: 휠로 확대/축소, 마우스로 끌어서 과거로 이동, 오른쪽 아래 화살표 버튼으로 현재 시간으로 복귀, "전체" 버튼으로 전체 기간 보기. 과거로 가면 이전 시세를 자동으로 이어서 불러옵니다.
  - 십자선: 차트에 마우스를 올리면 그 위치의 시간과 가격, 현재가 대비 %가 표시되고, 차트 위 한 줄에 그 봉의 시가/고가/저가/종가가 나옵니다.
  - 보유 중인 코인은 진입가(검은 점선), 익절가(빨간 점선), 손절가(파란 점선)가 그려지고 괄호 안에 진입가 대비 가격 변동률이 붙습니다. 숏 포지션은 가격이 내려야 익절이므로 익절선이 음수로 표시됩니다.
  - 원금 칸: 보유 포지션마다 투자 금액(증거금)과 현재 손익이 나란히 표시되고, 배율 옆 "청산" 버튼으로 그 포지션만 바로 정리할 수 있습니다. 직접 청산한 코인은 30분 동안 다시 진입하지 않습니다.
  - 왼쪽 아래에는 선택한 시간대의 시계(YYYY-MM-DD HH:mm:ss)가 항상 보입니다.
- **설정**: 레버리지 배율(1~50), 매매 방향(자동 / 롱만 / 숏만), 거래할 코인(다른 코인 추가 포함), 매수 방식(AI 자동 / 일괄 / 분할), 매도 방식(AI 자동 / 일괄 / 분할), 증거금 투자율(1~100%), 거래 횟수(1~100), 하루 거래 수익 설정과 하루 청산 설정(전체 원금 기준, 비율 또는 금액), 포지션 익절 / 손절(진입 투자금 기준, AI 자동 또는 수동), 포지션 보유 시간 제한(5~1440분), AI 상호 검증. 아래 "추가 설정"에 시간대와 거래 모드가 있습니다.
- **기록**: 1d / 1w / 1m / 1y 탭, 차트와 표 전환(표에는 진입 시각과 청산 시각이 따로 나옵니다), `엑셀로 정리` 버튼.
- **수익률**: 오늘 손익 현황(수익/손실/순손익, 코인별 막대와 원 그래프, 수익 표와 손실 표), 기간별 수익률, 오늘 실시간 수익률, 코인별 성과.
- **분석**: 글로벌 지수와 국제 금 시세, 실행한 거래마다 "왜 투자했는지" 설명, 오늘의 계획, 지난 회고와 학습 노트.
- **학습 자료**: 전략 글, 유튜브 링크, 차트 이미지를 올려 AI의 판단 기준으로 삼게 하는 곳.
- **모의투자 모드**: 모의투자를 켜고 끄는 스위치. On이면 실제 주문 없이 가상 잔고로 거래하고, Off면 저장된 Bybit 키의 계정으로 주문이 나갑니다. 같은 화면에서 자동 매매를 켜고 끌 수 있고, 가상 잔고와 누적 성과 확인, 시작 잔고 변경과 초기화도 여기서 합니다.
- **MAIL**: 일일 보고서를 받을 메일 주소를 넣는 곳. 주소를 적고 "추가"를 누르면 목록에 들어가고, 주소마다 "삭제" 버튼으로 지웁니다(최대 10개). 켜 두면 매일 21시(바꿀 수 있음, 선택한 시간대 기준)에 그날의 수익률, 거래 횟수, 승률, 주요 거래, 잘한 점, 실수와 개선점, 다음 방침을 목록의 모든 주소로 보냅니다. "오늘 보고서 미리보기"로 보내기 전에 내용을 볼 수 있습니다.
  - 간편 발송(기본): 비밀번호나 2단계 인증 없이 받는 주소만 있으면 됩니다. Gmail, 네이버, 다음 등 어떤 메일이든 됩니다. 무료 메일 전달 서비스(FormSubmit)가 대신 보내 주는 방식이라, 주소마다 처음 한 번은 그 주소로 확인 메일(제목에 Activate)이 오고 버튼을 눌러야 이후 보고서가 도착합니다. 보내는 사람은 FormSubmit으로 표시되고 보고서는 표 형태로 옵니다. 보고서 내용이 이 서비스를 거쳐 전달됩니다.
  - 내 메일 계정으로 발송(선택): 본인 Gmail, 네이버, 다음 계정으로 직접 보냅니다. 미리보기와 같은 모양으로 오지만 그 계정의 앱 비밀번호가 필요합니다.
- **API**: Bybit API Key/Secret과 Gemini API Key를 넣는 곳. 저장한 뒤 "연결 확인"을 누르면 잔고를 조회해 키가 맞는지 알려 줍니다(주문은 나가지 않음). Gemini 키는 저장하는 즉시 연결을 확인하고 결과를 초록색 "연결됨" 표시로 보여 줍니다. 키를 받는 순서도 이 화면에 적혀 있습니다.

### Bybit 키를 넣고 실제 계정에 연결하는 순서

1. 왼쪽 메뉴 **API**에서 Bybit API Key와 Secret을 붙여 넣고 "Bybit 키 저장"을 누릅니다.
2. 키를 만든 계정 종류(데모 트레이딩 / 실계정 / 테스트넷)를 고르고 "Bybit 연결 확인"을 누릅니다. 총자산이 표시되면 키가 맞는 것입니다.
3. 왼쪽 메뉴 **모의투자 모드**에서 "모의투자를 껐을 때 주문이 나갈 계정"을 같은 종류로 고르고, 모의투자 스위치를 Off로 바꿉니다.
4. 대시보드(또는 모의투자 모드 화면)에서 자동 매매 스위치를 On으로 바꿉니다.

### 모의투자를 하는 순서

1. 왼쪽 메뉴 **모의투자 모드**에서 모의투자 스위치가 On인지 봅니다(처음에는 On입니다). API 키가 없어도 됩니다.
2. 같은 화면의 자동 매매 스위치를 On으로 바꿉니다. 실제 시세로 가상 잔고가 거래를 시작합니다.
3. 결과는 메인, 기록, 수익률, 분석 화면에서 실전과 똑같이 볼 수 있습니다. 모의투자 기록과 실제 계정 기록은 따로 보관됩니다.
4. 처음부터 다시 하려면 시작 잔고를 적고 "이 잔고로 처음부터 다시 시작"을 누릅니다.

모의투자를 켜거나 끌 때는 자동 매매가 꺼진 상태로 바뀌고, 보유 중인 포지션이 있으면 먼저 정리해야 바꿀 수 있습니다.

### 거래 모드 (모의투자 모드 화면, 또는 설정 > 추가 설정)

| 모드 | 주문 | API 키 |
|---|---|---|
| 모의 투자 | 실제 시세로 프로그램 안에서만 체결 | 필요 없음 |
| Bybit 데모 트레이딩 | Bybit 가상 자금으로 실제 주문 흐름 | 데모 계정 키 |
| Bybit 테스트넷 | 테스트넷 | 테스트넷 키 |
| 실전 거래 | 실제 자금 | 실계정 키 |

안전 장치:

- Bybit API 키와 시크릿이 모두 있어야 모의 투자 외의 모드를 고를 수 있습니다.
- 실전 거래로 바꿀 때 확인 창이 뜹니다.
- 모드를 바꾸면 자동 매매는 꺼진 상태가 됩니다.
- 프로그램을 켤 때는 항상 Off로 시작합니다. 직접 On을 눌러야 거래가 시작됩니다.

### 권하는 순서

1. 모의 투자로 며칠 돌리며 화면과 기록을 익힌다.
2. Bybit 데모 트레이딩 키를 넣고 데모 모드로 실제 주문 흐름(주문, 손절/익절, 청산 기록)이 맞는지 확인한다.
3. 잃어도 되는 소액과 낮은 레버리지로 실전을 시작한다.

## 규칙이 어떻게 구현되어 있는가

**원금과 투자 비율**
- 기준 자산은 Bybit 통합 계정의 총자산(입금 원금 + 누적 수익금)입니다.
- 증거금 투자율이 20%, 동시 보유 포지션이 2개면 포지션 하나에 오늘 원금(그날 0시 총자산)의 10%를 증거금으로 씁니다.

**레버리지**
- AI 자동: Gemini가 그날 시장을 분석해 1배부터 설정한 상한(기본 50배) 사이에서 추천합니다. Gemini 키가 없으면 변동성으로 계산합니다.
- 수동 고정: 설정한 배율이 AI 추천보다 우선해서 모든 거래에 적용됩니다.

**손익 제한**
- 하루 손실이 한도(기본 -25%)에 닿으면 보유 포지션을 모두 청산하고 그날 매매를 잠급니다. 다음 날 0시(선택한 시간대)에 풀립니다.
- 새로 진입할 때는 "보유 포지션이 전부 손절돼도 남은 손실 한도를 넘지 않도록" 수량을 줄입니다.
- 급변동으로 가격이 손절가를 뛰어넘으면 실제 손실이 한도를 조금 넘을 수 있습니다.
- 목표 수익률에 도달하면 표시만 하고 계속 거래합니다. 설정에서 "달성하면 멈춤"을 켜면 포지션을 정리하고 그날 신규 진입을 멈춥니다.
- 하루 목표와 손실 한도는 비율(%)이나 금액(USDT)으로 정할 수 있고, 금액은 오늘 원금 대비 %로 바꿔서 적용합니다.
- 포지션마다의 익절/손절은 AI 자동(변동성과 차트 기준) 또는 수동(투자금 대비 비율이나 금액, 수수료를 뺀 순손익 기준)입니다. 모의투자는 5초마다 가격을 확인하므로 급하게 움직일 때는 정한 값보다 조금 지난 가격에 체결될 수 있습니다. 실제 계정에서는 손절/익절이 거래소에 걸립니다.

**수수료**
- Bybit 일반 등급 기준 테이커 0.055%, 메이커 0.02%를 기본값으로 씁니다. 실제 주문 모드에서는 계정의 수수료율을 조회해 씁니다.
- 모든 거래의 수익률과 순손익은 진입, 청산 수수료를 뺀 값입니다. 보유 중인 포지션도 같은 기준(청산 수수료는 현재가로 계산한 예상액)으로 표시합니다.
- 익절 폭이 왕복 수수료의 3배보다 작으면 넓혀서 주문합니다.

**거래 횟수**
- 진입과 청산이 한 쌍으로 끝나야 1회입니다. 하루 최대 횟수에 닿으면 새 진입을 멈춥니다.
- 하루 최소 횟수(기본 3회)에 못 미치는 속도면 진입 기준(확신도)을 최대 0.12까지 낮춥니다. 근거 없는 거래를 억지로 만들지는 않으므로 3회가 안 되는 날도 있습니다.
- 한 포지션은 설정한 보유 시간(기본 240분, 5~1440분)이 지나면 시장가로 정리합니다.
- 분할 매도로 나눠 판 포지션은 회차마다 기록이 남지만, 거래 횟수는 전부 정리된 때 한 번으로 셉니다.

**매매 방향**
- 자동: 롱과 숏을 같은 기준으로 평가해 고릅니다. 상승 추세면 롱, 하락 추세면 숏, 박스권이면 상단 숏과 하단 롱만 짧게, 두 방향의 근거가 비슷하면 관망합니다. 롱만 / 숏만: 그 방향으로만 진입하고, 반대 방향이 유리하다고 판단되면 진입하지 않고 기다립니다.
- 방향을 한쪽으로 고정하면 그 방향이 맞지 않는 장에서는 거래가 거의 없을 수 있습니다.

**실시간 시세**
- Bybit 공개 WebSocket(v5)으로 체결가를 받아 손절/익절 확인과 화면 표시에 씁니다. 감시 주기는 5초, 화면의 현재가는 1초마다 갱신됩니다.
- `websocket-client` 패키지가 없거나 연결이 끊기면 2초 간격 조회(REST)로 자동 전환됩니다. 대시보드 차트 오른쪽 위에 지금 어떤 방식으로 받고 있는지 표시됩니다.
- 모의투자도 같은 Bybit 실제 체결가를 씁니다. 가상으로 만든 시세가 아닙니다(가상 시세는 `selftest.py`에서만 씁니다).
- 그래도 Bybit 앱의 숫자와 완전히 같지는 않을 수 있습니다. 화면 갱신 간격(1초)과, 앱이 보여 주는 값(최근 체결가, 시장 평균가, 표시 통화)의 차이 때문입니다.

**Gemini 분석과 학습**
- 오늘의 계획: 미국 증시(나스닥, 다우, S&P 500)와 국제 금 시세(참고 지표) + 거래 대상 코인의 15분/1시간/일봉 지표 + 학습 노트 + 학습 자료.
- 진입 판단: 기본 15분마다 코인별 롱 확률과 숏 확률, 롱/숏/관망/청산과 이유. 프로그램의 규칙 점수와 맞춰 보는 상호 검증을 통과해야 주문합니다. 지표 요약과 함께 최근 캔들(15분봉 24개, 1시간봉 12개)의 시가/고가/저가/종가를 직접 넘겨 가격 행동을 볼 수 있게 했습니다.
- 과거 거래에서 배우기: 거래마다 진입 당시 시장 상황을 저장하고, 판단할 때마다 "같은 코인, 같은 방향"의 과거 성과(횟수, 승률, 평균 수익률, 추세와 같은 방향일 때와 반대일 때의 승률)를 Gemini에 함께 넘깁니다. Gemini 키가 없을 때 쓰는 규칙 전략도 승률이 낮았던 조합은 확신도를 낮춥니다.
- 하루 회고: 날짜가 바뀌면 전날 거래를 돌아보고 교훈을 "학습 노트"로 저장합니다. 이 노트가 다음 날 계획과 판단에 다시 들어갑니다.
- 일일 보고서: 정해 둔 시각(기본 21시)에 그날 거래를 복기해 메일로 보냅니다.
- "학습"은 AI 모델 자체를 훈련(파인튜닝)시키는 것이 아니라, 회고 노트와 과거 거래 성과를 쌓아 다음 판단의 참고 자료로 넣는 방식입니다. 별도의 벡터 DB는 쓰지 않고, 기록 DB에서 조건이 같은 거래를 찾아 집계합니다.
- Gemini 모델 이름은 `gemini-3.8-flash`가 기본입니다. 이름이 바뀌어 찾을 수 없으면 사용 가능한 Flash 모델을 자동으로 찾아 씁니다.

**유튜버 차트 분석 방법론**
- `methodologies.json`에 적힌 글이 매번 Gemini에 함께 전달됩니다. 영상 자체를 반영하려면 학습 자료 화면에 유튜브 링크를 올리세요(Gemini 키 필요, 공개 영상만). 올린 자료에서 뽑은 규칙은 아래의 일반 방법론보다 우선해서 쓰도록 지시합니다.
- `channels`에 참고 채널 4곳(DarkSideTrader77, easytradingeasy, FSD-XTrading, GoldAnalysis-n4k)을 넣어 두었습니다.
- `methodologies`에는 ICT/SMC, 프라이스 액션, 스캘핑, 금 흐름 참고 등 7개 항목이 들어 있습니다. 이 내용은 해당 기법의 일반적인 설명이고, 각 채널의 영상을 옮긴 것이 아닙니다. 영상을 보고 실제로 쓰는 규칙을 본인 말로 고쳐 적을수록 판단이 그 방식에 가까워집니다.

**시간대**
- 한국, 미국(뉴욕, 워싱턴, LA), 캐나다(밴쿠버, 토론토, 캘거리), 유럽(스페인, 독일, 영국, 프랑스, 이탈리아), UTC 중에서 고릅니다. 기본값은 한국입니다.
- 기록은 UTC로 저장하고 화면과 엑셀에는 선택한 시간대로 표시합니다. "하루"의 경계도 이 시간대의 0시입니다.

**기록**
- 거래마다 코인, 포지션(롱/숏), 레버리지, 수량, 진입 시각/청산 시각, 진입가/청산가, 사용 증거금, 사용 원금 비율, 수수료, 순손익, 수익률, 청산 사유, 진입 이유를 남깁니다.
- 엑셀 파일은 요약, 거래내역, 일별수익(차트 포함), 코인별 시트로 구성됩니다.
- 모의 투자와 실전 기록은 섞이지 않게 따로 보관합니다.

## Bybit 계정에서 확인할 것 (실제 주문 모드)

- 통합 거래 계정(UTA)이어야 합니다.
- USDT 무기한 선물의 포지션 모드가 **단방향(One-Way)**이어야 합니다.
- 프로그램이 낸 주문 외에 같은 코인을 손으로 거래하면 기록이 어긋납니다.
- 손절/익절은 주문과 함께 거래소에 걸리므로, 프로그램이 꺼져도 거래소에서 동작합니다. 다만 일일 손실 제한, 보유 시간 제한, AI 판단 청산은 프로그램이 켜져 있어야 동작합니다.

## 자주 겪는 문제

| 증상 | 확인할 것 |
|---|---|
| `ModuleNotFoundError` | 터미널 앞에 `(.venv)`가 있는지, `pip install -r requirements.txt`를 했는지 |
| 차트에 "시세를 불러오지 못했습니다" | 인터넷 연결, 그리고 현재 지역에서 Bybit 접속이 되는지 |
| Bybit 오류 10003 / 10004 | API 키 또는 시크릿이 틀렸거나, 데모 키를 실전 모드에 넣은 경우 |
| Bybit 오류 10010 | API 키에 걸어 둔 IP 제한과 현재 IP가 다름 |
| Bybit 오류 110007 | 잔고 부족. 증거금 투자율이나 레버리지를 낮춤 |
| "주문 금액이 최소 주문 단위보다 작습니다" | 자산이 작으면 BTC 최소 수량(0.001)에 못 미칩니다. 투자율이나 레버리지를 올리거나 자금을 늘림 |
| Gemini 오류 429 | 무료 사용량 초과. 설정의 판단 주기(분)를 늘림 |
| Gemini가 "연결 실패"로 표시 | API 연결 화면에서 "Gemini 연결 확인"을 눌러 나오는 문구를 확인. 키를 다시 복사해 저장 |
| 분석 화면의 지수가 "불러오지 못했습니다" | 카드에 적힌 이유를 확인하고 "새로고침"을 누름. 회사나 학교 네트워크에서는 시세 사이트가 막혀 있을 수 있음 |
| 수익률 화면에 원화가 안 나옴 | 환율을 받지 못한 경우. 달러 표시는 그대로 나옴 |
| 거래가 거의 없음 | 분석 화면의 "모든 판단"에서 실행하지 않은 이유를 확인. 상호 검증에서 계속 막히면 장세가 뚜렷하지 않은 것 |
| 유튜브 자료가 "분석 실패" | 공개 영상인지 확인. 긴 영상이나 사용량 초과면 실패할 수 있음. 핵심을 글로 적어 "전략 글"로 올리면 확실 |
| 코인 추가가 안 됨 | Bybit USDT 무기한 선물에 있는 약자인지 확인 (가격이 아주 작은 코인은 1000PEPE처럼 숫자가 붙기도 함) |
| 시간대 경고 | Windows에서는 `pip install tzdata` |
| 차트 오른쪽 위에 "2초 간격 조회 (REST)" | `pip install websocket-client` 후 다시 실행하면 실시간(WebSocket)으로 바뀝니다. 그대로 써도 동작합니다 |
| 확인 메일을 눌렀는데 "주소 확인 대기" | 간편 발송은 주소마다 처음 한 번 확인이 필요합니다. 그 주소의 받은편지함(또는 스팸함)에서 FormSubmit이 보낸 Activate 메일의 버튼을 누른 뒤 "확인 메일"을 다시 누릅니다 |
| 간편 발송이 계속 실패 | 메일 보고서 화면에 나온 실패 문구를 확인합니다. 전달 서비스가 요청을 받지 않으면 "내 메일 계정으로 발송" 방식으로 바꿔 쓸 수 있습니다 |
| 메일 "로그인에 실패했습니다" (내 메일 계정 방식) | 로그인 비밀번호가 아니라 16자리 앱 비밀번호를 넣어야 합니다. 2단계 인증이 켜져 있어야 만들 수 있습니다 |
| 21시에 메일이 안 옴 | 메일 보고서 화면의 스위치가 On인지, 그 시각에 `main.py`가 켜져 있었는지 확인. 실패하면 10분 간격으로 3번까지 다시 보냅니다 |
| 포트 사용 중 | `python main.py --port 8010` |

로그는 `data/myself_trade.log`에 남습니다. 모든 기록을 지우고 처음부터 시작하려면 프로그램을 끄고 `data` 폴더를 지우면 됩니다.
